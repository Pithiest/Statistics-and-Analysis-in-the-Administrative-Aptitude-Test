## 网站如何使用

网站提供训练录入、计时与快捷模板、训练总览、模块诊断、错题复盘、训练台账，以及 JSON 导入导出和 CSV 导出。

训练录入先保存在当前浏览器。需要多设备同步训练统计时，在各设备的设置页使用相同空间码。空间码是访问对应训练数据的凭据，应自行保管；这部分仍无需账号登录。切换浏览器、设备或域名不会自动继承原浏览器的本机数据。

在清理浏览器数据、迁移设备或做大范围数据整理前，先分别导出训练 JSON 和错题本 JSON。源码仓库和下面的工程备份只保存程序文件，不包含浏览器中的个人训练记录。

## 粉笔错题本

入口在「错题复盘 → 粉笔错题本」，原来的训练记录复盘保留在旁边的「训练复盘」标签。错题内容和复习次数不会计入训练题量、正确率或模块健康度。

连接流程是生成网站二维码，用自己的粉笔 App 扫描并在手机确认。每位使用者连接自己的账号，云端按账号分别保存题源与复盘进度。网站不收集粉笔密码，不将粉笔 Cookie 交给浏览器；已有 ChatGPT/Codex 插件的登录状态也不会自动复制到网站。网站的云端接入独立运行，设计上无需让个人电脑或 ChatGPT 保持开启。

当前同步范围为**行测的当前错题**：题干、选项、材料、解析、知识点与粉笔原作答。不会导入其他科目、全部历史练习，也不会替用户提交答题、修改粉笔作答或删除粉笔错题。来源中移除的题目仍保留在本网站，方便继续复盘。

- 完成首次同步后，云端按当前配置每 6 小时安排一次更新；「立即同步错题」可请求人工更新，短时间重复请求会合并。
- 粉笔会话失效或要求手机验证时，页面提示重新扫码。已有题目、笔记和复习记录继续保留。
- 「停止自动同步」会移除云端保存的粉笔会话，停止后续读取并保留已有错题；恢复时重新扫码。「退出此账号」注销当前网站会话并隐藏该账号记录，不等于停止该账号的后台同步。
- 先重做，再揭示答案与解析，随后选择「还没掌握」「有点吃力」或「已经理解」。安排分别为 10 分钟、1 天，以及逐步延长的 1、3、7、14、30、60 天。
- 笔记与复习记录先写入当前浏览器，再同步到当前账号。来源更新与复盘使用独立记录，重新导入或同步题目不会重置复习进度。

也可导入插件导出的错题 JSON 或本网站错题备份。未登录时的导入单独保存在本机，不会在登录时自动并入某个账号；登录后导入需要确认目标账号。导入文件中的题目内容仍只在本机保存，云端已有题目的复盘进度可合并同步。换设备前应导出需要保留的本机专有内容。

真实扫码、部署环境中的本人错题读取、跨设备进度同步及定时任务完整触发尚需分别验收；当前状态详见本轮更新记录。

## 本地开发与验证

在工程根目录使用 Node.js `22.18.0` 或更新版本与 npm。已保存依赖锁定文件，首次使用先安装锁定依赖：

```sh
npm ci
npm run dev
```

开发服务默认监听本机 `127.0.0.1`。根据改动范围执行验证：

```sh
npm test
npm run typecheck
npm run build
npm run preview
```

`dev`、`build` 和 `build:local` 都直接使用当前 Git 工作目录中的源码。`build:local` 保留为 `build` 的同功能入口；`preview` 打开构建结果。源码检查或构建通过后，还需要从浏览器实际验证受影响的入口。

正常开发、构建和发布均不从 Supabase 下载源码。`scripts/prepare-source.mjs` 不带 `--restore` 时直接退出，不写文件。历史恢复仅通过 `npm run source:restore` 显式执行；它会覆盖源码包列出的本地文件并处理包内删除清单，运行前应保留当前改动并确认恢复目标。`npm run source:pack` 仅把当前 `src/` 与 `public/` 打包为本地 `deploy-source.json`，不会自动上传。

## 部署关系

Vercel 托管网页，正式域名为 `xc.pithiest.cn`；GitHub 保存可维护源码，发布分支更新关联 Vercel 部署。Supabase 项目 `atwsraivphybkfmyeubd` 提供原训练空间码同步，以及独立的 `fenbi-cloud` 错题服务。

Vercel 配置使用 `npm ci` 安装、`npm run build` 构建并发布 `dist/`。原 `materialize-source.yml` 文件现为 **Verify source** 工作流，只有仓库读取权限，运行测试、类型检查和构建，不再生成或推回源码提交。

前端发布不会自动发布 Supabase 数据库与 Edge Function。粉笔云端改动还需单独部署 `supabase/schema/fenbi_cloud.sql` 与 `supabase/functions/fenbi-cloud/`，核对业务鉴权与定时任务，再验证真实入口。`fenbi-cloud` 使用自有会话鉴权，部署时关闭平台 JWT 校验不代表开放业务数据匿名访问。

粉笔账号、扫码事务和站内会话使用独立服务端表，匿名与普通登录数据库角色均无直接读写权限。站内会话令牌只存哈希，并绑定一个账号；粉笔会话通过 AES-GCM 加密，密钥由 Supabase Vault 提供。题源与复盘进度分列保存；更新题源不能覆盖复盘，进度写入通过版本条件处理多设备并发。浏览器使用按账号隔离的 IndexedDB 保存错题，并缓存自己的站内会话令牌。

历史部署使用 Supabase 表 `xingce_sync` 中的 `pithiest-xingce-source-v5` 保存源码包。它与个人训练同步数据共用表，但用途不同，现在只保留作手动恢复来源。显式恢复会优先读取云端包，其次尝试本地 `deploy-source.json`，两者都不存在时保留仓库源码。普通界面维护无需更新该云端源码包。

发布后应打开正式域名，检查受影响页面、刷新、加载资源与手机布局。GitHub 或 Vercel 的成功状态表示构建发布成功，不代替真实入口验收，也不证明所有网络环境都可访问。

## 数据与维护边界

- 本机数据和同步设置由浏览器保存，代码恢复或工程归档不等于数据备份。
- Supabase 故障可能造成同步失败；应用会保留本机数据。整站超时还需分别检查域名、网络路径和前端资源。
- 检查接口可使用无记录返回的只读请求。未经明确需要，不读取、解密、上传或改写真实训练内容。
- `.env`、访问令牌、真实空间码与个人训练导出文件不提交到 Git，不写入日志、截图或公开文档。
- 本机备份与历史截图予以保留。需要恢复源码时先保留当前工作，再核对备份范围。
